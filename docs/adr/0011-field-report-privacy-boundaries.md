# ADR-0011: 現地報告では投稿日時と投稿者の横断導線を表示しない

## ステータス

承認済み

## コンテキスト

[[現地報告]]（車中泊スポットに対する、実際に訪れたユーザーの公開の書き込み）を導入するにあたり、「いつ・どこに・誰が」を画面にどこまで出すかを決める必要がある。

現地報告は、このサービスで初めて **複数ユーザーの声が同じスポットのページに並ぶ機能** である。そして書き手の表示には ADR-0003 の[[作成者ハンドル]]を流用する（常に匿名・ユーザーは選べない・実名の選択肢は設けない）。ハンドルは `owner.id` から決定的に生成されるため、**同一ユーザーには常に同じハンドルが付く**。

ここから、単独で車中泊する利用者にとって軽視できない露出が生じうる。

- **投稿日時の表示**：訪問時期を「年月」の粒度に丸めても、`createdAt` を「3分前に投稿」のように画面へ出せば、実質「この人はいまそこにいる」という宣言になる。年月粒度で得た保護が一行下で無効化される。
- **ハンドルの横断一致**：公開旅程の作成者ハンドルと、複数スポットの現地報告のハンドルが一致する。突き合わせると一人の利用者の移動の軌跡が復元されうる。公開旅程には日付入りの詳細な行程が含まれる。

一方、緩和要因もある。ADR-0003 のハンドル名前空間は接頭辞40×動物30＝**約1,200通りしかなく、衝突を許容している**。同名が量産されるため「同じハンドル＝同じ人」と断定できない。名前空間が狭いことが、偶然の防御として働いている。

検討した案：

- **案A**: 投稿日時をそのまま表示し、「この投稿者の他の報告」導線も設ける。一般的なレビューサイトの作法で、実装も自然
- **案B**: 投稿日時は表示するが横断導線は設けない。中途半端で、上記の「いまそこにいる」問題が残る
- **案C**: 投稿日時を表示せず、横断導線も設けない

## 決定

**案C** を採用する。

1. **訪問年月を必須で持ち、既定値を「今月」とする。** 画面に出す時間情報は訪問年月だけとする。日・週の粒度は持たない。
2. **投稿日時（`createdAt`）を公開画面に表示しない。** DBには保持する。用途は「同一訪問年月内の並び替え」と「レート制限などのスパム対策」に限る。
   - **例外: 管理画面（`/admin/*`）に限り投稿日時を表示してよい。** スパム・荒らしの判断には「短時間に連投されているか」が実際に効き、訪問年月だけでは連投が見えない。本 ADR が守るのは「他の利用者から現在地・軌跡を読まれること」であり、管理者はそもそもDBを直接見られる立場なので脅威モデルが異なる。ただしこの例外は `/admin/*` 限定であり、公開画面には決して出さない。
3. **「このハンドルの投稿一覧」を作らない。** 現地報告から、その書き手の他の投稿・他の旅程へ辿る導線を一切設けない。
4. **投稿直後の本人にだけ、自分の報告が反映されたことが分かるようにする。** 他人に見えるのは訪問年月のみで変わらない。
5. ハンドル名前空間の拡大や衝突解消（登録テーブル・サフィックス付与）は**行わない**。ADR-0003 の衝突許容をそのまま維持する。
6. **投稿者の識別子は Auth0 の `sub` のみを保存し、`name` / `email` は保存しない。** `sub` は「同一スポット・同一訪問年月に1件」の制約判定、本人による削除、投稿間隔の制限、通報の重複防止、悪質な投稿者の特定に必要である。管理者が投稿者を特定する必要が生じた場合は `sub` から Auth0 Management API で引けるため、メールアドレスを事前に複製しておく理由はない。
7. **`sub` をクライアントへ送らない。** サーバー側でハンドルへ変換し、payload に載せるのは `handle` 文字列だけとする。ADR-0003 が公開旅程で塞いだ穴が、現地報告では「公開スポットページに複数ユーザーの識別子が一覧で並ぶ」形で再現しうるため、より厳格に守ること。
8. **管理者が現地報告を非表示にした場合、投稿者本人からも見えなくする。** 本人にだけ見え続ける方式（投稿単位のシャドーバン）は採用しない。誤判定が誰にも検出されないまま固定されること、および「同一スポット・同一訪問年月に1件」の制約により本人が書き直すこともできなくなることを避けるため。非表示の理由の通知も初版では行わない。

## 理由

- 現地報告の価値は「**いつ行ったか**」であって「いつ書いたか」ではない。投稿日時を隠しても失うものがほぼない一方、得られる保護は具体的である
- 訪問年月の粒度は、「その人が今日どこにいるか」を語らない。日・週の粒度にすると保護が壊れるため、粒度を細かくしない判断を含む
- 横断導線は「実装しない」決定なのでコストがゼロである。後から足すのは容易、剥がすのは困難という非対称性があるため、最初は付けない側に倒す
- 名前空間を広げないことで、衝突による曖昧さが軌跡の追跡を難しくし続ける。ここでの「一意性のなさ」は欠陥ではなく保護である

## トレードオフ

- 「最近書かれたか」が読者に分からない。同じ訪問年月の報告のうちどれが新しい観察かは表示上区別できない
- 「この人の他の報告も読みたい」という自然な要望に応えられない。書き手側の継続的な評判・信頼の蓄積も起きない（現地報告の信頼は書き手ではなく訪問年月と内容に置く、という立場）
- ハンドル衝突は残るため、同一スポットの報告一覧に同じハンドルが並び、別人が同一人物に見えることがある

## 注意

投稿日時を非表示にしているのと、投稿者の横断導線を設けていないのは、**親切さを削ったのではなく安全装置である**。「何分前に投稿されたか出したほうが親切」「この人の他の報告も見たい」という要望で安易に追加すると、単独で車中泊する利用者の現在地と移動の軌跡が露出する。変更時はこのADRと ADR-0003 を参照すること。
