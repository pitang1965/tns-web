# ADR-0009: AI旅程ドラフト生成の初期コスト・アクセス方針とサブスク前提

## ステータス

承認済み（実装は未着手。設計段階の判断として記録する）

## コンテキスト

[ADR-0008](0008-itinerary-draft-generation-architecture.md) の旅程ドラフト生成は、心臓部でLLM API（従量課金）を呼ぶ。本アプリの運営方針には次の制約がある。

- **Vercel Hobby は非商用前提**。広告・アフィリエイトはWebから外しAndroidアプリに集約することで、Webの非商用の建付けを維持している（プロジェクト方針）。Webに「公開・無料・従量課金」の機能を置くことは、この方針と緊張する。
- 「お金がかかる機能はサブスク導入後にする」という運営者の原則がある。LLM APIはまさに従量課金であり、この原則と正面から関わる。

一方で、この機能の主目的は「LLM APIを活用したAI機能を実装し実績を作る」ことであり、作って動かし見せられる状態にすることが必要である。

コスト実測（[ADR-0008](0008-itinerary-draft-generation-architecture.md) の構成、`claude-haiku-4-5`、入力$1・出力$5/100万トークン、1ドル150円換算）：

- 1回の生成 ≒ 入力6,000 + 出力1,500トークン ≒ **約2円/回**。リトライや大きめの旅程でも〜4円/回。
- 参考：`claude-opus-4-8`（入力$5・出力$25/100万）だと約10円/回（Haikuの約5倍）。

## 決定

**初版は管理者／ホワイトリスト限定で公開する。**

1. **アクセス範囲**：初版は管理者（および明示的に許可したユーザー）のみが生成機能を使える。公開課金は発生させない。これにより「AI実績づくり」と「コスト原則・Web非商用方針」を両立する。

2. **モデル**：初版は `claude-haiku-4-5`（コスト・速度重視）。1回2円なら管理者の検証を月数百回行っても数百円で、実質無視できる。

3. **アクセス判定とレート制限の口を1箇所に集約する**：アクセス可否（初版は管理者判定）と「1ユーザー/日N回」等のクォータを1つの関数にまとめる。サブスク導入時に、この関数の条件を「管理者限定→有料会員＋クォータ」へ差し替えるだけで公開できるようにしておく。

4. **API配置**：生成は内部の Server Action（`generateItineraryDraft`、`src/app/actions/`）とする。`/api/v1/`（[ADR-0006](0006-versioned-mobile-api.md) のモバイル専用・後方互換凍結・APIキー保護の契約）には置かない。実装時に Vercel の関数実行時間上限を確認する（LLM生成は10〜30秒かかりうる。Haiku＋出力量抑制で対処、超えるならストリーミング等を検討）。

5. **鍵の扱い**：`@anthropic-ai/sdk` を追加。`ANTHROPIC_API_KEY` は `.env.local` のみに置き、git追跡ファイルには決して書かない（既存の `MONGODB_URI` と同じ方針）。

**将来のサブスク導入の前提（本ADR時点の合意。数値は目安）：**

- **回数上限はコストではなく乱用防止で決める**。1回2円なので原価から回数を決める必要はない。実際の使い方（旅の計画時に数回＋再生成）から、**月30回で実質使い放題に感じる**（迷えば50回）。
- **採算ラインを決めるのはLLMコストではなく固定費と決済手数料**：
  - Web課金は商用利用に当たり、Vercel Hobby（無料・非商用）の前提が崩れる。**Vercel Pro（約$20/月≈¥3,000）が必要になりうる**。
  - Stripe決済手数料 約3.6%/件、消費税10%。LLM API代は課金者あたり月60〜300円で無視できる。
- **価格の目安は月¥500（税込）**。心理的に軽く、¥500なら手数料・税引後の実収~¥450で、**約7〜10人の課金者でVercel Pro代＋手数料を回収**できる。
- **課金の置き場所（未決の戦略分岐）**：
  - **Web課金（Stripe）**：手数料は安い（3.6%）が、Web非商用の建付けが崩れ Vercel Pro が必要。
  - **Androidアプリ課金（Google Play）**：「商用はAndroidに集約」という既存方針と整合するが、Play手数料15〜30%が乗る。
  - 「機能はWeb先行・課金はどこか」のねじれをどう解くかは、モバイル展開計画とセットで別途決める。

**将来の最適化として保留する項目（サブスク導入・利用ボリューム増の後に検討）：**

- 道路距離API（Mapbox Directions等）による経路精度の向上（[ADR-0008](0008-itinerary-draft-generation-architecture.md) は直線＋回り道係数）。
- ローカルLLM（例：22万円クラスのMac Mini＋量子化モデル）によるLLMコストの0化。技術的には可能だが、速度（数十秒〜数分でWeb要求のタイムアウトを超え非同期化が必要）・構造化出力の信頼性・常時起動の運用負担があり、プロトタイプ段階では早い。LLM呼び出しをプロバイダ抽象の裏に置き、後で差し替え実験ができるようにしておく。

## 理由

- 管理者限定なら公開課金ゼロで完成した実物を作れ、AI実績づくりの目的を達しつつ、Webに公開・従量の機能を置かない（非商用方針を崩さない）。
- レート制限とアクセス判定の口を最初から1箇所に用意しておけば、サブスク実装時の変更が条件差し替えに限定される。
- 価格・回数を「LLM原価」ではなく「固定費回収＋体感価値」で設計するのが、1回2円という実測から導かれる正しい設計軸である。

## トレードオフ

- 初版は一般ユーザーが使えない。公開はサブスク（または方針判断）を待つ。
- Web課金 vs Play課金の分岐を先送りしている。サブスクを実際に始める段では、この決定を確定させる必要がある（手数料構造とVercelの商用/非商用が大きく変わるため）。

## 注意

Webで課金を開始することは、Vercel Hobby の非商用前提を崩す。サブスク導入時は Vercel のプラン（Pro必要性）と、広告・アフィリエイトをAndroidに集約している既存の商用線引きとの整合を必ず確認すること。安易にWeb課金を足すと、非商用で保っているはずの建付けが静かに崩れる。
